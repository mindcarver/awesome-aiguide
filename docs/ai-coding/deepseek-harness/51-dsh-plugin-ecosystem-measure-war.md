# dsh 插件生态：四千个插件、五个市场和一场度量战争

> `dsh` 开源约一个月，插件生态冲到近四千个登记插件、一万三千多个打了标签的仓库、五个第三方市场，而官方没有开市场。更拧巴的是度量：星数榜的头部被挂标签的无关产品占据，一个 3.5 万星的项目被实证与 `dsh` 没有一行代码关系；按 npm 周下载排序的榜单才还原真实装机，第一名每周二十万次。本篇按 2026 年 9 月 5 日的快照盘点：度量为什么失真、谁在真实被安装、哪些项目确认真身、oh-my-dsh 为什么被官方点名却只有 14 颗星，以及一套挑插件的实际判断。生态月增是数量级的，数字用过即弃，判断方法比数字耐用。

## 星数榜在撒谎

假设你要给 `dsh` 装一个侧边栏工作台插件。打开聚合市场 dshget，按 star 排序，榜首是一个 4.2 万星的项目：reactive-resume，一个开源简历构建器。它和 `dsh` 的关系是零，唯一的连接是它的仓库挂了 `dsh-plugin` 这个 GitHub topic 标签。

这不是孤例。3.54 万星的 DeepSeek-Reasonix 也挂在榜单头部，实际查证过：它是一个独立的 Go 语言编码 agent，有自己的扩展协议、Go SDK 和 ACP 实现，README 通篇没有提到 `dsh`。挂标签的成本是一次点击，收益是进入一个二十一万星仓库辐射出的流量池。于是简历工具、图床工具、低代码平台都来了。

`dsh-plugin` 这个 topic 是 DeepSeek 官方创建的开放标签，任何人都能给自己的仓库挂上，而聚合市场直接抓取 topic 并按星数排序。两个机制叠在一起，星数作为"插件热度"的信号就废了：它度量的不再是"多少 `dsh` 用户装了它"，而是"多少 GitHub 用户给这个项目点过星，以及这个项目想不想蹭流量"。

星数榜上也有真项目，后面会讲到 9.4 万星的设计引擎这种货真价实的插件。问题不是榜上全假，而是排序已经失真：你无法从头部的星数推断任何东西。

## 生态的真实尺寸

先把盘子铺开，数字都以 2026 年 9 月 5 日为准。

官方仓库本身约 21 万星（9 月初，话题页与讨论页两个来源交叉一致）。打了 `dsh-plugin` 标签的仓库 13,760 个，语言分布是 JavaScript 7,795、TypeScript 4,610、Python 543、Rust 106。写插件的主战场是 TS 和 JS，这与 `dsh` 的插件机制一致：插件是 Cordis 包，进 Node 进程。

市场有五家以上。dshget 收录 3,993 个插件、23 个分类，聚合四个来源；dshmarket 收录 3,019 个、24 个分类，每天 CI 刷新；另有 deepseek404、dsh.so、dsh-plugins.org 三家目录，数据普遍滞后（dsh-message-edit 在其中一家记 13 星，实测 49）；还有商业公司 SpringBrand 把自己的 OAuth MCP 插件市场整个装进 `dsh`。注意一个有趣的递归：插件市场之上又长出了插件，"市场与管理器"在 dshget 自己就是一个分类，67 个条目，装一个插件来管理你从市场装的插件。

官方没有市场。官方开的通道是 GitHub Discussions 的插件秀场（#3113、#3456 这些帖子），索引全靠社区：事实上的总账本是 awesome-dsh-plugin，14.5k 星，收录 2,663 个插件，每日 CI 刷新，234 个 open PR 排队等合并。一个没有官方店的生态，账本由志愿者维护，这本身决定了后面所有度量的混乱。

## 下载榜：谁在真实被装

dshmarket 做了一件关键的事：不按星数排，按 npm 周下载排。插件从 npm 安装，下载量就是装机量，这个口径绕开了蹭标签的干扰。

榜单头部（周下载，2026 年 9 月初）：DSH-better-sidebar 207,883 次，侧边栏工作台，文件编辑、终端、Git 一个不少；dsh-task-board 205,086 次，看板加上 cron 定时调度 agent 会话；dsh-remote-web-ui 203,984 次，手机扫码远程控制；dsh-git-graph 200,623 次；dsh-skill-explorer 145,439 次。

两个观察。第一，下载榜头部的星数只有 3,267，与星数榜头部的四万级差一个数量级。星数和装机严重脱钩：真被装的东西不太涨星，涨星的东西不太被装。第二，前十里有一半出自同一个作者（zhu1090093659），一人四件：task-board、remote-web-ui、git-graph、skill-explorer。插件作者生态不是长尾散沙，出现了多产作者，这是职业化的早期信号。

回到开头的问题：装哪个侧边栏工作台？答案在下载榜第一位，不在星数榜任何位置。

## 真认真身的项目

以下是经查证确认存在的项目，按"它们说明生态的什么"分组。

消息编辑双雄。`dsh` 官方曾实现会话消息编辑，随后 revert，官方立场是把这类功能让给插件生态。承接的两个项目走了不同路线：DSH-EasyRewrite（96 星）做原位编辑加惰性撤回，被官方秀场帖子转发，是增长最快的插件之一；dsh-message-edit（49 星、19 fork）做分支式编辑，消息长成版本树，还暴露 HTTP API。同一个需求两条产品路线，生态多样性的标本。

大厂把 `dsh` 当集成目标。火山引擎官方的 OpenViking（35.5k 星），自进化上下文数据库，仓库里带着真实的 `dsh-memory-plugin` 示例。这是目前最大厂的背书：不是给 `dsh` 贡献代码，而是把自己的产品做成 `dsh` 的下游。

出圈的非 coding 项目。open-design，9.4 万星，自称设计领域的开源替代，把编码 agent 变成设计引擎，导出 HTML、PDF、PPTX、MP4；archify，4.8 万星，生成架构图、时序图、数据流图。`dsh` 的分类学里非编程插件合计五百多个，这两个是天花板。

桥接与发行层。dsh-desktop（23.6k 星）做桌面端，口号是"桌面本身也是插件"；dsh-acp 让 Zed 经 JSON-RPC 驱动 `dsh`；deepseek-harness-sdk-go 补上官方没有的 Go SDK。fork 方向倒是安静：2.49 万个 fork 里，没有找到确认"fork 魔改成自己产品"的实例。

## oh-my-dsh：被官方点名，只有 14 颗星

生态里最拧巴的项目。官方 rc.1 的 release notes 点名了它并声明非官方，Discussions 秀场也给它开帖，但它只有 14 颗星、0 个 fork、59 个 commit。

它是一个治理型发行版：Skill Forge 和 Plugin Forge 让 agent 提案新技能新插件、人来审批；带 Eval 和 Optimizer；MCP 懒激活；能复用你已有的 Claude、Codex、Gemini 配置。工程姿态也认真：钉住 `dsh@0.1.0-rc.8`，每周用 canary 跑上游 next 分支，主动管理 pre-1.0 的冲刷风险。

它的口号值得单独记下："Overlay, not a fork"。不 fork 源码，一切改造发生在插件层和覆盖层。这和上一节 fork 方向的安静互为印证：整个生态的共识是改造在插件层做，这也是"一切皆插件"架构意图的胜利。

名气与体量的倒挂说明两件事。生态还早，官方一句点名比社区一万颗星更有权威性；以及"发行版"这条路本身没被验证，用户更愿意单装插件而不是换一个发行版。

## 痛点的另一面

生态的痛点全部来自 pre-1.0 的冲刷，社区讨论里有完整记录。

破坏性变更是明牌。README 全大写写着会有兼容性破坏，0.0.1 到 0.1.x 之间命名重构频繁，Discussions #5120 整帖在问"插件怎么跟上版本"。版本追踪曾是重灾区：上游长期只推 master 单分支、不打 tag，npm 与 git 不同步，单独安装某个 `@deepseek-ai/dsh-*` 包会安静拿到旧版，错配以类型错误的形式延迟爆炸。

插件 API 有真实缺口。#802 指出：插件能声明合并自己的会话事件类型，但持久化这些事件可能导致其他进程打不开会话。插件作者面临两难，要么放弃领域事件，要么冒写坏会话的风险。官方后来恢复了可忽略事件标记，给了非关键事件一条安全通道，核心事件仍无官方答案。

稳定性是结构性风险。#1884 综述了 AI 生成插件的风险：插件跑在宿主进程里，一个未捕获异常波及全进程所有会话。#1814 报告过实际事故：装了一个依赖 `dsh-tools` 的插件，全部工具调用被弄坏。文档缺口由社区填补：CSDN 文档合辑、runoob 教程站、一本社区编的 DeepSeek Harness Handbook。

## 痛点长出了新插件

这个生态最健康的信号，是痛点本身催生了诊疗工具链。

DSH Doctor 识别版本之间的 API 变化并自动迁移插件；dsh-plugin-reducer（#3686）用最小插件集做二分诊断，定位是哪个插件弄坏了宿主；topology（#1565）画插件依赖图；AgentDebugX 是一个学术演示（EMNLP 2026 demo），做 agentic AI 的调试。

调试工具链的出现比插件数量更有含金量。四千个插件说明人多，自建的诊疗工具说明这些人在认真长期地用，而不是发完即弃。

## 挑插件的一套判断

把全文收成可执行的清单。

看下载不看星。星数榜已被标签流量污染，npm 周下载是装机量，dshmarket 的口径目前最干净。看作者的插件列表，多产作者的质量信号强于单品的星数。问它声明测试过的 `dsh` 版本，pre-1.0 阶段这是必答题，答不出来的插件默认会坏在下个 release。看市场姿态，锁注册表、默认禁 build script、不收遥测的 dshmarket，比照单全收的聚合器可信。AI 生成的插件先隔离观察，#1884 的教训是一个未捕获异常、全进程所有会话买单。

最后一条关于数据本身：本文所有数字是 2026 年 9 月 5 日的快照，这个生态的月增速是数量级的，任何数字用前重查。判断方法比数字耐用，这也是本文把方法放在数字前面的原因。
