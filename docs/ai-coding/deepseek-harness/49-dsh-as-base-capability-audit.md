# dsh 当基座：能力审计与三条红线

> 把 DeepSeek Harness（`dsh`）从"每天打开的 CLI"变成"自己产品底下的基座"，要回答的是另一组问题：产品怎么把它装进来（Python SDK、headless、ACP、Web 插槽、工具插件，五个进入面）；装进来之后能拼什么（自动化、状态、配置分发，三块底座）；以及哪里会翻车（三条红线：它不肯当服务器，地基每几天动一次，执行面只会一种语言）。本篇按 v0.1.3-alpha.1（2026 年 9 月 4 日）的源码和官方文档逐项判定，每项给可用、勉强、不可用三档结论。总判定：单用户桌面工具今天就能盖；多用户服务要么自己包一层，要么再等。

## "当基座"是另一件事

同一个 `dsh`，两类用户的处境完全不同。

CLI 用户打开 Web 界面或终端，和 agent 对话，让它读代码、改文件、跑命令。会话怎么持久化、界面长什么样、版本怎么升级，全是官方的事。

基座用户反过来：`dsh` 住在你的产品里当 agent 引擎。你的代码创建会话、发任务、收结果；你的界面面向你的用户；你把一整套配置打包分发给别人。会话生命周期归你管，升级节奏也被迫归你管。官方为 CLI 用户做的所有取舍，现在都变成你的约束。

什么时候你从第一类变成第二类？三条判定线，命中任何一条就算：你的进程在驱动会话，而不是人在输入框里打字；你要加自己的领域工具或改界面；你要把配置打包发给别人。

本文用一个贯穿案例撞每一项审计：交易工作台。行情获取、策略研究、信号输出、下单风控，这是一个会把所有支持面都撞一遍的设想。而且截至成文，公开生态里没有任何人把 coding harness 当基座做过交易产品；框架层的知名项目（TradingAgents、ai-hedge-fund）全部止步于产出信号和模拟盘。每个审计项都会问一句：交易台在这项上能不能落地。

审计基于 v0.1.3-alpha.1 的源码和官方文档，判定三档：可用，官方支持且没有重大缺口；勉强，有路但有明确代价；不可用，官方明确拒绝或能力缺失。

## 五个进入面：产品怎么把 dsh 装进来

五个进入面按嵌入深度排，从"整个引擎住进你的进程树"到"往它身上拧一颗螺丝"。

### Python SDK：整个引擎住进你的进程树

判定：可用，带两个条件。

`deepseek-harness-sdk` 发布在 PyPI 上，工作方式是起一个 `dsh` 子进程跑 sdk profile，父子进程之间用按行分隔的 JSON-RPC 通信。你的 Python 代码创建会话、发任务、按到达顺序收事件通知，子 agent 的后代事件也收得到。配套的 `runtime-bin` 包把 `dsh` 和 Node 运行时打成单个可执行文件，目标机器不用装 Node；SDK 与 runtime 精确同版本互锁，装的就是严格匹配的版本对，不存在半新半旧。

交易台对应：Python 服务里起 SDK，接收研究请求，驱动 agent 会话。"后端 agent 引擎"这条路成立。

两个条件都写在文档里。第一，SDK 的接口全部同步阻塞，没有异步版本，要并发就多起子进程，进程池自己管理。第二，自定义工具不能在 Python 侧注册，工具必须用 TypeScript 写成 Cordis 插件（`dsh` 的插件机制，插件向共享上下文贡献服务和工具）装进 profile。一句话：用 Python 指挥，用 TypeScript 扩展，控制面和扩展面是两种语言。

平台覆盖：linux x64 与 arm64、macOS arm64 与 x64、Windows x64 都有 wheel，Windows arm64 没有。

### headless 与 sdk profile：进程外的两种姿势

判定：可用。

`dsh --profile headless "任务"` 是一次性执行：跑完退出，stdout 打最终答案，退出码 0 或 1，不开端口，不能追问。注意输出是纯文本不是 JSON，要结构化结果就走 SDK。它适合外层 cron 和 CI 调用。交易台"每天收盘后跑一次复盘"这种动作，headless 是自然选择，定时逻辑归外层。

`dsh --profile sdk` 是编程式 JSON-RPC：先协商模型和参数，再发任务，等到空闲状态结算。任何语言只要会说 JSON-RPC 都能驱动，不绑定 Python。

### ACP：接进编辑器，只当控制面

判定：可用，边界清晰。

ACP（Agent Client Protocol）是编辑器和 agent 通话的标准协议。`dsh --profile acp` 让 `dsh` 作为 server 被 Zed 这类客户端驱动：一条连接多个会话，支持列出、恢复、关闭会话，设置模型，弹权限询问，挂 MCP server。协议文档同时写明它的定位是 automation-only，wire 上不暴露任何私有展示数据，聊天卡片、任务清单、计划这类界面数据拿不到。

交易台对应：把 `dsh` 接进自己的编辑器或自研客户端当控制面，可以；想拿 ACP 当产品界面的数据源，不行。

### Web 插槽：改得了聊天，加不了页面

判定：勉强。

Web 界面的扩展机制是插槽（slots），一套类型化的 React 组合系统。官方界面本身就是用插槽树搭的：侧栏、会话区、详情区、覆盖层，插件往这些位置注册自己的组件。设计内的用法很清楚：会话流里的自定义卡片（行情、持仓、盈亏曲线就往这挂），自定义工具的调用卡片，输入框附近的动作按钮。

边界在插槽树的形状上：树里没有"新增一个独立页面"的位置。想要一整页的下单台，只能 fork 官方布局包，把现有插槽当替换点。fork 在 pre-1.0 下的代价，红线二里算。

交易台对应：聊天内嵌卡片是设计内用法，代价小；独立工作台布局超出扩展面。

### 工具插件与 MCP：扩展面里最硬的一块

判定：可用，五个面里最硬的。

自研工具走 TypeScript Cordis 插件：注册工具，参数自动校验，输出归一化 JSON，自带界面卡片钩子。关键是执行前的策略钩子，allow、deny、ask 三种裁决。交易台的下单工具就在这里挂风控：金额超限 ask，黑名单品种 deny。旁边还有一个更硬的 guard 接口，裁决一旦 deny 就单调不可放行。

MCP（Model Context Protocol，给 agent 接外部工具的开放协议）消费是现成的：`dsh` 是 MCP client，stdio 和 Streamable HTTP 都支持，一个 server 一行配置，工具自动以 `mcp__<server>__<工具名>` 的名字进工具表，调用 60 秒超时，断线自动重连。stdio 方式起的 MCP 子进程会做环境变量清洗，名字里带 KEY、PASSWORD、SECRET、TOKEN 的变量直接剥掉。

交易台对应：这是最顺的一块。Binance 官方的 Agent OS MCP 提供专用子账户，可下真实订单；Alpaca 官方 MCP 有 61 个端点，支持 paper key；QuantConnect 的 MCP 有 60 多个端点，回测和实盘部署都能走。行情和下单全部经 MCP 接入，一行对接代码不用写。

MCP 的边界：只桥接工具，resources 和 prompts 不桥。

## 能力底座：装进来之后能拼什么

进入面解决"怎么进来"，底座解决"进来之后用什么"。三块，每块的强弱分界都清楚。

自动化。三个部件，分界线是人是否在场。jobs 是会话内后台任务，bash 和子 agent 两种，每个发起会话默认并发 10。workflow 让模型在一次回合内写编排脚本，agent、parallel、pipeline 一类原语，带并发上限和致命错误纪律，"十个标的并行研究再汇总"这种活是它的形状。schedule 是会话内定时，after、at、every 三种粒度，最小间隔 300 秒，没有 cron 表达式；官方文档直说原会话必须活着，没有外部通知通道，也没有冷会话调度器，错过的事后只补最新一次。交易台对应："打开工作台研究一轮出信号"成立；"每天早上八点自动跑"不成立，定时要用 headless 加外部 cron 自己造。

状态与分发。会话持久化是 append-only 事件流，JSONL 格式带可选压缩，当前格式版本 v2 且带旧版迁移，支持 fork 和恢复，有全文检索索引。跨会话记忆没有内置，官方给的是三个默认关闭的第三方记忆 MCP 和一份接入指南，基座用户要么选一个要么自己上。凭证有专门的缝：API key 用环境变量名做引用，每次使用时解析，设置界面只见描述不见值。交易所 key 放这里，不进代码不进提示词。配置分发两条路：profile 是模板加补丁层；preset 是目录形式的整装配置，可以指向公司内部目录做统一来源，拿去分发"交易台全套配置"，机制是现成的。

一句话收束：底座最硬的是挂工具、管凭证、打包配置，最弱的是无人值守。

## 红线一：它不肯当服务器

三个事实，都是官方写死的。

出厂 CLI 拒绝把 Web 服务绑到 0.0.0.0，`dsh web` 默认只听本机回环。webserver 的文档写明载体进程自身不带 TLS、认证和 Origin 策略；配置面允许改绑定，但安全责任全部归组装的人。Web 界面支持多会话、多 workspace，那是同一个用户的多会话，不是多租户；浏览器侧有每次启动轮换的令牌和签名 cookie，但那是单用户本机姿态的认证。

这是定位，不是缺陷。`dsh` 当前明确定位是单用户本地工具，安全公告（SAFETY.md）还写着它没有经过安全审计，不能按生产系统对待。

绕法只有两条。单用户桌面工具和内网单人部署是设计内用法，直接盖。要多用户服务，就用 SDK 或 headless 在自己的服务里包一层：agent 会话当引擎，用户体系、鉴权、租户隔离全部在你那层完成。别试图把 `dsh` 的 Web 界面直接暴露给多个用户。

## 红线二：地基每几天动一次

节奏先摆出来：8 月 19 日到 9 月 4 日，十个 release。README 用全大写写着 THERE WILL BE COMPATIBILITY-BREAKING CHANGES。近两周的破坏性变更实例：会话持久化 API 改成生命周期作用域的句柄模型，SQLite 持久化后端整个移除，会话格式升 v2。这些不是边角料，全是基座用户最依赖的地基。

升级痛还有一层机制。官方全仓 252 个包锁步发版，但 npm 的 latest 标签不跟着预发布走，单独安装某个 `@deepseek-ai/dsh-*` 包会安静地装到旧版本；错配不报安装错误，以类型错误的形式延迟爆炸。插件作者也有记录在案的两难（GitHub Discussion #802）：插件声明自定义事件容易，但把它持久化进会话，可能导致别的进程打不开这个会话。官方 8 月底恢复了可忽略事件标记，给了一条安全写非关键事件的路；核心领域事件仍然没有官方持久化通道。

对基座用户，含义就是一句话：每次跟版都是一次源码级 diff。三个缓解，按性价比排。第一，走 Python SDK 这条路，runtime 精确版本互锁，升级是一个整体动作。第二，扩展面踩得越浅冲刷越小：能用 MCP 解决的不写深度界面插件，能挂插槽的不 fork 布局。社区最大的发行版 oh-my-dsh 的口号是"Overlay, not a fork"，overlay 的跟版成本远低于 fork，这是用脚投票的结果。第三，把跟版写进 CI，每周对上游 diff 一次自己的扩展面。这笔税在 pre-1.0 阶段省不掉。

## 红线三：执行面只会一种语言

最容易混的一点：两个"Python"不是一回事。

控制面的 Python：SDK 用 Python 指挥 `dsh`。有，成熟。执行面的 Python：code-runtime 跑模型写的代码，发布的后端只有 TypeScript 一种，跑在 worker thread 里；Python 后端在仓库里实现了，但官方文档的原话是它是实验性的、私有的，没有任何出厂配置挂载它。

交易台在这里撞得最疼：量化生态，回测框架、因子库、券商和交易所接口，在 Python；模型在代码执行模式里写的策略是 TypeScript。三个绕法。让模型经 bash 调系统 Python，沙箱策略要覆盖这条路。把 Python 能力包成 MCP server，回测引擎和数据源做成工具，模型调工具。或者等 Python 后端发布。

这个领域还有一条注脚：agent 碰真金白银的事故有公开复盘，自主交易 agent 单次亏损百万美元量级的案例记录在案，社区共识是先模拟盘、人工审批、规则限额。`dsh` 真正有竞争力的点恰好在这：执行前策略钩子和单调 guard 是 harness 级原语，审批门挂在引擎里，不是外挂脚本。这也是"当基座"和"用 CLI"的实质差别之一，基座用户拿到的风控挂点，和官方自己用的是同一套。

## 判定表：你的产品能不能盖

| 产品形态 | 判定 | 关键依赖 |
|---|---|---|
| 单用户桌面工具，领域助手或个人工作台 | 今天就能盖 | 工具插件、MCP、插槽卡片，preset 分发 |
| 单机自动化流水线 | 能盖，定时自造 | headless 加外部 cron，结构化输出走 SDK |
| 嵌进编辑器的控制面 | 能盖 | acp profile |
| 带界面的单用户工作台 | 勉强 | 卡片形态是设计内用法，整页布局要 fork 并付跟版税 |
| 多用户服务或 SaaS | 今天不行 | 自己包服务层，或等官方的服务化姿态 |

交易工作台对号入座：研究、信号、风控审批、凭证管理全是绿灯，工具插件、MCP、执行前钩子、凭证缝都是现成原语；整页下单台黄灯，插槽不够，fork 有税；无人值守定时黄灯，外层自造；多账户服务红灯。

比表更实用的一条判断标准：数你的产品需要 `dsh` 的哪几层。只要工具挂架、审批门、凭证、会话持久化，踩得浅，今天就能盖，冲刷可控。一旦需要整页界面或多用户，你就在用它的未来下注。

## 边界：判定会过期，性能要自测

这份审计有保质期。pre-1.0 的意思是，任何一条"不可用"都可能在下个版本翻过来：服务化姿态和 Python 执行后端已经以实验形态存在于仓库里。判定依据是源码和文档，不是路线图承诺；翻新这份表的成本不高，盖产品前值得重查一遍。

性能和成本本文没有测。同步 SDK 的吞吐上限、子进程的资源占用、多会话并发时的行为，选型前要自己压一轮。

安全公告的原话适合放在这里收尾：`dsh` 没有经过安全审计。资金敏感场景，审批和限额层任何时候都不能省，这一条与版本号无关。
